# Diracord — referência para IAs (llm.txt)

Diracord é uma linguagem de texto para criar bots de Discord. Este arquivo descreve a
linguagem v0.1 exatamente como o motor atual a aceita. Ao escrever código Diracord, siga
estas regras. Fonte da verdade: docs/SPEC.md; funções e erros abaixo são gerados do código.

## 1. Projeto

```
meu-bot/
  diracord.toml        # configuração
  .env                 # DISCORD_TOKEN=... (nunca no código, nunca no git)
  commands/ping.dcs    # qualquer arquivo .dcs, .dira ou .diracord em qualquer pasta
  events/join.dcs
```
Todos os arquivos são carregados juntos. Não existe import.
CLI: `diracord new <pasta>`, `diracord check [--fix]`, `diracord run`, `diracord watch`.

diracord.toml (todas as chaves são opcionais; valores padrão mostrados):
```toml
ram = "100mb"
[bot]
name = "meu-bot"
prefix = "!"
[commands]
prefix = true          # comandos com prefixo: !ping
slash = true           # slash commands: /ping
[syntax]
dollar = false         # liga o atalho $ban[user;reason]
[data]
path = "data/bot.dirabank"
default_scope = "user" # user | server | member | global
[limits]
time_ms = 3000
steps = 100000
memory_kb = 4096
actions = 50
[discord]
intents = ["guilds", "guildMessages", "messageContent", "guildMembers"]
```

## 2. Léxico

- Comentário: `//` até o fim da linha. Não existe comentário de bloco.
- Nomes: letra ou `_`, depois letras, dígitos ou `_`. Diferencia maiúsculas: `memberJoin` ≠ `memberjoin`.
- Palavras reservadas: command fn local if else for in while chain testing try catch
  return stop break continue true false null and or not
  (`button`, `menu` e `modal` só são especiais no topo do arquivo, como `button("id") { }`;
  dentro do código, `button(...)` é a peça de Components v2.)
- Números: `15`, `1.5`, `1_000`. Ids do Discord são TEXTO: `"123456789012345678"`.
- Texto: só aspas duplas `"..."`, numa linha. Escapes: `\n \t \" \\ \$`.
- Interpolação: `$nome` ou `$nome.campo.campo` dentro do texto. Para o símbolo $, use `\$`.
  Não existe `${expr}`: para expressões, use `+` ou uma variável local.
- Quebra de linha separa instruções. `;` também separa (para várias numa linha).

## 3. Gramática (EBNF)

```ebnf
program     = { item } ;
item        = command | event | interaction | function ;
command     = "command" "(" STRING { "," param } [ "," ] ")" block ;
param       = NAME ":" argtype [ "=" expr ] ;          (* com "= valor" fica opcional; opcionais no fim *)
function    = "fn" NAME "(" [ fnparam { "," fnparam } ] ")" block ;
fnparam     = NAME [ ":" argtype ] [ "=" expr ] ;      (* tipo opcional; opcionais no fim *)
argtype     = "text" | "number" | "bool" | "member" | "user" | "channel" | "role" ;
event       = EVENT_NAME block ;                       (* nome direto, sem palavra-chave *)
interaction = ( "button" | "menu" | "modal" ) "(" STRING ")" block ;

block       = "{" { stmt ( NEWLINE | ";" ) } "}" ;
stmt        = "local" NAME "=" value
            | target "=" value
            | "if" cond block { "else" "if" cond block } [ "else" block ]
            | "for" NAME "in" cond block
            | "while" cond block
            | "chain" cond "{" { arm [ "," ] } "}"
            | "testing" block "catch" [ NAME ] block
            | "return" [ value ]
            | "stop" | "break" | "continue"
            | value ;
arm         = pattern "=>" ( block | stmt ) ;          (* vários casos podem ficar na mesma linha *)
pattern     = "_" | ["-"] NUMBER | STRING_SEM_$ | "true" | "false" | "null" ;
target      = NAME { "." NAME | "[" expr "]" } ;

value       = bare_call | expr ;                       (* só onde a gramática diz "value" *)
bare_call   = NAME arg { [ "," ] arg } ;               (* chamada SEM parênteses; termina na quebra de linha *)
cond        = expr ;                                   (* em condições, "{" abre o bloco, não um objeto *)

expr        = or ;
or          = and { ( "||" | "or" ) and } ;
and         = equality { ( "&&" | "and" ) equality } ;
equality    = compare { ( "==" | "!=" ) compare } ;
compare     = sum { ( "<" | "<=" | ">" | ">=" ) sum } ;
sum         = product { ( "+" | "-" ) product } ;
product     = unary { ( "*" | "/" | "%" ) unary } ;
unary       = ( "-" | "!" | "not" ) unary | postfix ;
postfix     = primary { "." NAME | "[" expr "]" | "(" [ arg { "," arg } [ "," ] ] ")" } ;
              (* "[" de índice vem colado: lista[0]. "(" na mesma linha. *)
primary     = NUMBER | STRING | "true" | "false" | "null" | NAME
            | "(" expr ")" | "[" [ expr { "," expr } [","] ] "]"
            | object | dollar_call ;
object      = "{" { ( NAME | STRING ) ":" expr ( "," | NEWLINE ) } "}" ;
arg         = [ NAME ":" ] expr ;                      (* argumento nomeado: scope: user *)
dollar_call = "$" NAME [ "[" [ arg { ";" arg } ] "]" ] ;  (* só com [syntax] dollar = true *)

```

## 4. Regras de significado

- `reply "oi"` == `reply("oi")`. Em chamada sem parênteses, os argumentos são separados por
  espaço (vírgula opcional) e cada um é uma expressão completa: `reply "Oi " + user.name` OK.
  Uma chamada dentro de outra precisa de parênteses: `reply upper("oi")`. ERRADO: `reply upper "oi"`.
- Chamada sem parênteses só no começo da instrução, depois de `local x =`, `x =` e `return`.
  Em `if`/`while`/`for`/`chain` use parênteses: `if hasRole(user, "VIP") { ... }`.
- O nome de uma função sozinho é uma chamada sem argumentos: `deleteMessage`, `now`.
- Variáveis: `local x = 1` cria (vale até o fim do bloco); `x = 2` muda uma que já existe.
  Mudar campo/posição: `obj.campo = 1`, `lista[0] = 1` (a posição precisa existir).
- Tipos dinâmicos: null, bool, number (inteiro ou decimal), text, list, object.
  Tipos só existem nos argumentos de `command(...)`.
- Falso: `null`, `false`, `0`, `""`, `[]`. Todo o resto é verdadeiro.
- `+` soma números; se um lado é texto, junta textos; listas concatenam.
  `- * / %` só números. `7 / 2` = 3.5; `6 / 2` = 3. Dividir por 0 é erro E0203.
- `==` compara por valor (`1 == 1.0` é true). `<` `>` funcionam entre números ou entre textos.
- `and`/`or` (ou `&&`/`||`) param cedo e devolvem true/false.
- `for x in lista`, `for letra in "texto"`, `for i in 5` (0..4), `for chave in objeto`.
  Para intervalos: `for i in range(1, 6)` (1..5).
- `chain x { 1 => reply "um"  "a" => reply "letra"  _ => reply "outro" }`: o primeiro caso igual
  ganha; `_` = qualquer outro e deve ser o último. Não há "fall-through".
- `testing { ... } catch err { ... }`: `err` é o TEXTO da mensagem de erro. Erros de limite
  (tempo, passos, memória, ações) NÃO podem ser pegos.
- `stop` encerra o comando/evento. `return valor` também encerra. `break`/`continue` só em laços.
- Embeds: `reply { title: "Oi", description: "...", color: "red", footer: "rodapé",
  image: "https://...", thumbnail: "https://...", fields: [{ name: "a", value: "b", inline: true }],
  timestamp: true }`. Cores: red green blue blurple yellow orange purple pink white black gray,
  "#rrggbb" ou número.
- Menções: o bot só menciona usuários (nunca @everyone/@here/cargos).

## 4.1 Components v2

Peças no estilo do discord.js: cada peça é uma função que devolve um valor, e uma vai
dentro da outra. `reply`/`send` aceitam uma peça, uma lista de peças ou `{ layout: [...] }`.
```dcs
command("rules") {
  reply container(
    text("## Welcome, $user.name"),
    section("Read the rules.", thumbnail: user.avatar),
    separator(spacing: "large"),
    row(button("accept", "Accept", style: "success"), button(label: "Website", url: "https://example.com")),
    color: "purple"
  )
}
```
Onde cada peça pode ficar:
- Na mensagem: container, section, row, text, separator, gallery, file.
- Dentro de container(...): section, row, text, separator, gallery, file (NÃO container, NÃO button/menu soltos).
- section(textos..., thumbnail: X ou button: Y): 1 a 3 textos e exatamente UM acessório.
- row(...): até 5 button(...), OU um menu(...) sozinho.
- button(id, label, ...) só em row(...) ou em section(button: ...). Com url: é link e não tem id.
- O clique de button("id") / menu("id") roda o handler `button("id") { }` / `menu("id") { }` do topo do arquivo;
  em menus, os escolhidos ficam em `message.values`.
Layout não se mistura com texto ou embed: para texto, use text(...). Máximo 40 peças por mensagem.
A forma objeto (para gerar por código) é equivalente:
`reply { layout: [ { container: [ { text: "## Hi" }, { row: [ { button: "ok", label: "Ok" } ] } ], color: "purple" } ] }`

## 4.2 Funções próprias (fn)

```dcs
fn giveCoins(who: member, amount: number = 1) {
  local total = get("coins", 0, scope: user) + amount
  set("coins", total, scope: user)
  return total
}

fn greet(name) {
  return "Hi $name"
}

command("daily") {
  local total = giveCoins(user, 100)
  reply greet(user.name) + "! You have $total coins."
}
```
- Ficam no topo de qualquer arquivo e valem no projeto todo. Chamada igual às embutidas:
  `giveCoins(user, 10)`, `giveCoins user 10`, `giveCoins(who: user, amount: 10)`.
- Tipos são opcionais e iguais aos de `command` (text, number, bool, member, user, channel,
  role). Com tipo, `"10"` vira `10`; tipo errado é E0302 apontando a chamada.
- A função só enxerga os próprios argumentos, os próprios `local` e as variáveis automáticas
  (`user`, `server`, `channel`, `message`). NÃO enxerga os `local` de quem chamou.
- `return valor` devolve o resultado (sem `return`, devolve `null`). `stop` dentro da função
  encerra o comando inteiro. Recursão é permitida, até 64 chamadas aninhadas (E0211).
- Não pode ter o nome de uma função embutida (`fn reply(...)` é E0116). Use `fn`, não `function`.

## 5. Variáveis automáticas

Dentro de command, eventos e button/menu/modal:
- `user` (alias `author`): quem disparou. Campos: id, name, username, mention, bot, avatar;
  em servidor também nick, roles (lista de ids), joinedAt.
- `server`: id, name (null em mensagem privada). Não existe `guild`: o nome é sempre `server`.
- `channel`: id, mention (e name, type quando conhecidos).
- `message`: id, content, channelId, authorId. Em interações, `interaction` = `message`;
  em menus, `message.values` é a lista escolhida.
- Em reactionAdd/reactionRemove: `reaction.emoji`. Em roleCreate/roleDelete: `role`.
- Argumentos de `command` viram variáveis com o mesmo nome.

Tipos de argumento de comando: text, number, bool, member, user, channel, role.
No prefixo, o último argumento `text` recebe o resto da linha: `!ban @Zé spam de link`.

## 6. Eventos

ready, messageCreate, messageUpdate, messageDelete, memberJoin, memberLeave, memberUpdate,
reactionAdd, reactionRemove, channelCreate, channelDelete, roleCreate, roleDelete,
voiceJoin, voiceLeave.
Vários arquivos podem ter o mesmo evento: todos rodam, na ordem dos arquivos.

## 7. Dados salvos (Dirabank)

`get(nome, padrão?, scope?)`, `set(nome, valor, scope?)`, `delete(nome, scope?)`.
Escopos: `user` (por usuário), `server` (por servidor), `member` (usuário dentro do
servidor), `global` (um valor para o bot todo). Sem `scope:`, usa `[data] default_scope`.
Em `scope: user`, `user` é a palavra do escopo, não a variável.
```
set("coins", get("coins", 0, scope: user) + 1, scope: user)
```

## 8. Limites de cada execução (padrão)

100000 passos, 3 s de CPU (esperar o Discord não conta), 4 MB em variáveis,
50 ações no Discord, 64 KB por valor salvo. Passar disso para a execução (E0204–E0206).
Comandos: no máximo 5 por usuário a cada 10 s.

## 9. Funções embutidas

Formato: assinatura -> retorno : descrição. `?` = opcional. Todas aceitam argumentos
por nome (`get("x", scope: user)`). Tipos: user/channel/role aceitam o objeto, o id em
texto ou a menção (`<@id>`, `<#id>`, `<@&id>`); role aceita também o nome do cargo.

## 11. Erros comuns (errado → certo)

- `let x = 1` / `var x = 1` → `local x = 1` (E0100, corrigido por --fix)
- `try { } catch err { }` → `testing { } catch err { }` (E0100, corrigido por --fix)
- `function hi(x) { }` → `fn hi(x) { }` (E0100, corrigido por --fix)
- `fn reply(x) { }` → escolha outro nome; `reply` é embutida (E0116)
- usar dentro da `fn` uma variável `local` de quem chamou → passe como argumento (E0200)
- `if x = 1 { }` → `if x == 1 { }` (E0100, corrigido por --fix)
- `x = 1` sem criar antes → `local x = 1` (E0200, corrigido por --fix)
- `rpely "oi"` → `reply "oi"` (E0201, com sugestão)
- `memberjoin { }` → `memberJoin { }` (E0113, corrigido por --fix)
- `command(ping) { }` → `command("ping") { }` (E0109)
- `command("a", x: string)` → `command("a", x: text)` (E0107, corrigido por --fix)
- `command("a", x: text = "", y: member)` → opcionais por último (E0112)
- `reply 'oi'` → `reply "oi"` (aspas simples não existem, E0002)
- `reply upper "oi"` → `reply upper("oi")` (chamada dentro de chamada)
- `if hasRole user "VIP" { }` → `if hasRole(user, "VIP") { }`
- `reply "Total: ${a + b}"` → `local t = a + b` e `reply "Total: $t"`, ou `reply "Total: " + (a + b)`
- `"custa $5"` → `"custa \$5"` (E0005, corrigido por --fix)
- `reply "oi"` fora de um command/evento → coloque dentro de `command("x") { ... }` (E0114)
- `$ban[user;motivo]` com o atalho desligado → `ban(user, motivo)` (E0108, corrigido por --fix)
  ou ligue `[syntax] dollar = true`
- `user.nmae` → `user.name` (E0209, com sugestão)
- `lista.length` → `len(lista)`
- `chain x { _ => ...  1 => ... }` → `_` sempre por último (E0110)
- `break` fora de for/while → `stop` (E0115)
- `get("x", scope: guild)` → `scope: server` (E0401)
- `guild.name` / `$guild.name` / `scope: guild` → `server` (E0200/E0401, corrigido por --fix)
- `reply container(button("a", "A"))` → `reply container(row(button("a", "A")))` (E0117, seta no botão)
- `section("a")` sem acessório → `section("a", thumbnail: url)` ou `section("a", button: button("b", "B"))`
- `container("texto solto")` → `container(text("texto solto"))`
- `reply "Oi", row(...)` → `reply [text("Oi"), row(...)]` (layout não mistura com texto solto)
- Ids grandes como número (`123456789012345678901`) → use texto `"123..."` (E0003)

## 12. Exemplos

```dcs
command("ping") {
  reply "Pong!"
}

command("ban", user: member, reason: text = "sem motivo") {
  testing {
    ban user reason
    reply "$user.name foi banido. Motivo: $reason"
  } catch err {
    reply "Não consegui banir: $err"
  }
}

command("dado", lados: number = 6) {
  local n = random(1, lados)
  chain n {
    1 => reply "1... azar!"
    _ => reply "Saiu $n"
  }
}

command("perfil") {
  reply {
    title: "Perfil de $user.name"
    color: "blurple"
    fields: [{ name: "Moedas", value: get("coins", 0, scope: user), inline: true }]
  }
}

memberJoin {
  local ch = channel("welcome")
  if ch {
    send ch "Bem-vindo, $user.mention!"
  }
}

button("confirm") {
  reply "Confirmado!" ephemeral: true
}
```

## 13. Ainda NÃO existe (não use)

- Plugins WASM.
- Funções como valor (`local f = giveCoins`): funções só podem ser chamadas.
